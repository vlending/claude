# OGQ 블렌딩용 Karpathy LLM Wiki 운영 가이드

## 1. 개요

이 문서는 Andrej Karpathy의 **LLM Wiki** 아이디어를 OGQ 블렌딩 조직/프로젝트 환경에 맞춰 실행 가능한 형태로 정리한 운영 가이드입니다.
핵심은 "질의 시점에 매번 문서를 재검색하는 방식"을 넘어, LLM이 지속적으로 관리하는 **누적형 위키(knowledge artifact)** 를 구축하는 것입니다.

---

## 2. 핵심 원칙

### 2.1 RAG 중심 운영의 한계
- 질문이 들어올 때마다 원본 문서를 다시 찾고 조합해야 함
- 문서가 많아질수록 동일한 맥락을 반복 재구성하게 됨
- 조직 지식이 "채팅 로그"로 흩어지고 축적되지 않음

### 2.2 LLM Wiki 방식
- LLM이 원본 소스를 읽고 위키 문서를 **직접 생성/갱신**
- 개체/주제/정책/프로젝트 페이지를 **상호 링크**
- 상충 정보(버전 차이, 정책 변경)를 위키 안에서 표시
- 질문 결과(비교표, 분석 결과)도 재편집해 위키에 재적재

즉, "검색 기반 일회성 답변"이 아니라 "지식 베이스를 컴파일하고 유지"하는 방식입니다.

---

## 3. OGQ 블렌딩 적용 아키텍처

### 3.1 Layer A: Raw Sources (불변 원천)
- 대상: 회의록, Slack 스레드 요약, 정책 문서, 제품 PRD, 고객 인터뷰, 분석 리포트
- 규칙: **원본은 수정하지 않음(immutable)**
- 목적: 감사/추적 가능한 진실의 기준점

예시 경로:
```text
knowledge/raw/
  policies/
  product/
  meeting-notes/
  customer/
```

### 3.2 Layer B: Wiki (LLM 관리 영역)
- 대상: 주제 요약, 팀별 운영 원칙, 기능 히스토리, 용어 사전, 의사결정 로그
- 규칙: LLM이 생성/수정, 사람은 리뷰/승인
- 목적: 사람이 읽기 쉬운 구조화된 지식 레이어

예시 경로:
```text
knowledge/wiki/
  index.md
  log.md
  entities/
  concepts/
  decisions/
  playbooks/
```

### 3.3 Layer C: Schema (운영 규약)
- 대상: 파일 규칙, 인제스트 절차, 링크 규칙, 충돌 처리 방식, 답변 템플릿
- 권장 파일: `AGENTS.md` 또는 `CLAUDE.md`
- 목적: LLM을 "일반 챗봇"이 아니라 "지식 관리자"로 고정

---

## 4. 표준 운영 플로우

### 4.1 Ingest (소스 반영)
1. 원본 문서를 `knowledge/raw/`에 추가
2. LLM에게 "인제스트" 지시
3. LLM 수행 항목:
   - 원본 요약 페이지 생성
   - 기존 관련 페이지 교차 업데이트
   - 변경 근거/출처 링크 반영
   - `log.md`에 타임스탬프 기록
4. 담당자는 변경 diff 검토 후 merge

### 4.2 Query (질의/보고)
1. LLM이 `index.md` 우선 확인
2. 관련 위키 페이지 조회 후 종합 답변 생성
3. 고가치 결과물(비교표, 정책 FAQ, 인사이트)을 위키에 재저장

### 4.3 Lint (정합성 점검)
주기적으로 다음을 검사:
- 상충되는 주장
- 갱신되지 않은 정책(구버전)
- 고립 페이지(링크 없음)
- 자주 언급되지만 독립 페이지가 없는 핵심 개념
- 출처가 약한 주장(근거 미흡)

## 5. 필수 파일 설계

### 5.1 `index.md` (콘텐츠 인덱스)
- 카테고리별 페이지 목록 + 한 줄 설명
- 위키의 "목차 + 검색 출발점" 역할

권장 항목:
- 페이지 링크
- 마지막 업데이트 날짜
- 소스 개수
- 오너(팀/담당자)

### 5.2 `log.md` (작업 연대기)
- append-only 형식 유지
- 인제스트/질의/린트 이벤트를 시간순으로 기록

권장 헤더 형식:
```markdown
## [2026-04-20] ingest | 2026Q2 온보딩 정책 변경안
```

이 형식을 쓰면 CLI로 최근 작업 확인이 쉽습니다.

## 6. OGQ 블렌딩 운영 규칙(권장)

### 6.1 문서 규칙
- 모든 위키 페이지는 최소 1개 이상의 출처를 명시
- 주장성 문장에는 가능한 한 source backlink 첨부
- "확정 사실"과 "가설/의견"을 분리 표기

### 6.2 역할 분담
- Human: 소스 큐레이션, 중요도 판단, 최종 승인
- LLM: 요약, 링크 연결, 중복 정리, 충돌 표시, 문서 일관성 유지

### 6.3 변경 관리
- 위키 변경은 Git PR 기준으로 운영
- 대규모 인제스트는 배치보다 "소량 연속" 권장
- 분기별로 스키마(`AGENTS.md`)를 리팩터링
